# ระบบบันทึกข้อมูลนิสิต — คู่มือติดตั้ง

ไฟล์ในโปรเจกต์นี้:
- `index.html` — แดชบอร์ดสำหรับเจ้าหน้าที่ (หน้าแรกของเว็บไซต์ ต้องกรอกรหัสผ่านก่อนเข้าดู)
- `add-student.html` — ฟอร์มสาธารณะให้นิสิตกรอกข้อมูลเอง (ไม่ต้อง login) เข้าถึงได้จากปุ่ม "เพิ่มข้อมูลนิสิต" ในแดชบอร์ด
- `Code.gs` — Apps Script backend (เขียน/อ่านข้อมูลใน Google Sheet)
- `appsscript.json` — manifest ของ Apps Script

---

## ขั้นตอนที่ 1 — สร้าง Google Sheet + Apps Script

1. สร้าง Google Sheet ใหม่ (ตั้งชื่อเช่น "ฐานข้อมูลนิสิต")
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเดิมทั้งหมด แล้ววางเนื้อหาจาก `Code.gs`
4. เพิ่มไฟล์ manifest: กดไอคอนรูปเฟือง (Project Settings) → ติ๊ก "Show appsscript.json" → กลับไปหน้า Editor → เปิดไฟล์ `appsscript.json` → วางเนื้อหาจากไฟล์ที่ให้มา
5. ในไฟล์ `Code.gs` แก้ค่า `DASHBOARD_PASSCODE` เป็นรหัสผ่านที่ต้องการ แล้วแจ้งรหัสนี้ให้เจ้าหน้าที่ที่ควรเข้าถึงแดชบอร์ดได้

## ขั้นตอนที่ 2 — การยืนยันตัวตนแดชบอร์ด (โหมดชั่วคราว)

ตอนนี้แดชบอร์ดใช้ **รหัสผ่านร่วมชั่วคราว** (ตั้งค่าใน `DASHBOARD_PASSCODE` ใน `Code.gs`) แทนการ login ด้วย Google — เพื่อให้เริ่มใช้งานและแก้ไขฟีเจอร์อื่นๆ ได้เลยโดยไม่ต้องไปตั้งค่า Google Cloud Console ก่อน

**ข้อจำกัดของโหมดนี้ที่ควรรู้:**
- ทุกคนที่รู้รหัสผ่านเห็น/แก้ไข/ลบข้อมูลนิสิตได้เหมือนกันหมด ไม่แยกสิทธิ์รายบุคคล
- ไม่มี audit log ว่าใครเป็นคนแก้ไขจริง (คอลัมน์ `lastEditedBy` จะบันทึกเป็น "เจ้าหน้าที่" ทั่วไปเสมอ)
- ถ้ารหัสผ่านหลุดหรือถูกแชร์ต่อ ใครก็เข้าถึงข้อมูลอ่อนไหว (เลขบัตร ปชช. ฯลฯ) ได้ทันที

**เมื่อพร้อมใช้งานจริง** (โดยเฉพาะถ้ามีนิสิตจำนวนมากหรือข้อมูลอ่อนไหวเยอะ) แนะนำให้อัปเกรดเป็นการ login ด้วย Google บัญชี @ku.th จริง (ตรวจสอบ idToken ฝั่งเซิร์ฟเวอร์ ไม่ใช่แค่เช็ค client-side) — แจ้งเมื่อพร้อมแล้วให้ช่วยเปลี่ยนกลับได้ทุกเมื่อ

## ขั้นตอนที่ 3 — Deploy Apps Script เป็น Web App

1. ใน Apps Script Editor → มุมขวาบน **Deploy → New deployment**
2. เลือกประเภท (Select type) → **Web app**
3. ตั้งค่า:
   - Execute as: **Me**
   - Who has access: **Anyone**
4. กด **Deploy** → อนุญาตสิทธิ์ (Authorize) ตามที่ระบบขอ
5. คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)
6. นำ URL นี้ไปแทนที่ `REPLACE_WITH_YOUR_DEPLOYMENT_ID` ใน **สองที่**:
   - `index.html` → ตัวแปร `APPS_SCRIPT_URL`
   - `add-student.html` → ตัวแปร `APPS_SCRIPT_URL`

> ทุกครั้งที่แก้โค้ดใน Apps Script ภายหลัง ให้กด **Deploy → Manage deployments → แก้ไข (ไอคอนดินสอ) → Version: New version → Deploy** เพื่อให้ URL เดิมใช้โค้ดใหม่ (ไม่ต้องเปลี่ยน URL ในหน้าเว็บอีก)

## ขั้นตอนที่ 4 — Deploy หน้าเว็บบน GitHub Pages

1. สร้าง repository ใหม่ใน GitHub แล้วอัปโหลด `index.html` และ `add-student.html`
2. ไปที่ **Settings → Pages** → เลือก branch ที่ต้องการ (เช่น `main`) → Save
3. เข้าถึงแดชบอร์ดได้ที่ `https://yourname.github.io/repo/` (เป็นหน้าแรก)
4. เข้าถึงฟอร์มกรอกข้อมูลนิสิตได้ที่ `https://yourname.github.io/repo/add-student.html` หรือกดปุ่ม "เพิ่มข้อมูลนิสิต" จากในแดชบอร์ด

## ประเด็นความปลอดภัยที่ควรทราบ

ระบบนี้เก็บข้อมูลอ่อนไหว (เลขบัตรประชาชน, เบอร์โทร) จึงมีมาตรการดังนี้:

- **ฟอร์มกรอกข้อมูล** เปิดสาธารณะ แต่ backend ตรวจสอบเลขประจำตัวนิสิตซ้ำเพื่อกันการยื่นซ้ำ/ปลอมแปลงข้อมูลเดิม
- **แดชบอร์ด** ตอนนี้ตรวจสอบด้วยรหัสผ่านร่วม (`DASHBOARD_PASSCODE`) ที่เช็คฝั่งเซิร์ฟเวอร์ทุกครั้งที่เรียก API — ปลอดภัยกว่าการเช็คแค่ฝั่ง browser แต่ยังไม่แยกสิทธิ์รายบุคคล (ดูรายละเอียดในขั้นตอนที่ 2)
- เลขบัตรประชาชนในตารางแดชบอร์ด **ปิดบังเป็นค่าเริ่มต้น** (โชว์แค่ 4 หลักท้าย) กดเพื่อดูฉบับเต็มได้ทีละรายการ ลดความเสี่ยงคนแอบดูผ่านไหล่
- ควรจำกัดสิทธิ์การเข้าถึง Google Sheet เอง (Share) ให้เฉพาะเจ้าหน้าที่ที่จำเป็น เพราะแดชบอร์ดเป็นเพียงหน้าต่างหนึ่งในการเข้าถึงข้อมูล ไม่ใช่การควบคุมสิทธิ์ที่ตัว Sheet
- แนะนำเปิด "ประวัติเวอร์ชัน" (Version history) ของ Sheet ไว้เผื่อข้อมูลถูกแก้ไข/ลบผิดพลาด

## ข้อจำกัดที่ควรรู้

- ปัจจุบันฟีเจอร์ "เจ้าหน้าที่ตรวจ/แก้ไข" ยังไม่ได้แบ่งสิทธิ์ตามภาควิชา/อาจารย์ที่ปรึกษา (บุคลากร @ku.th ทุกคนที่เข้าแดชบอร์ดเห็นข้อมูลทั้งหมด) — หากต้องการแบ่งสิทธิ์ละเอียดกว่านี้ (เช่น อาจารย์เห็นเฉพาะนิสิตในที่ปรึกษาของตน) แจ้งมาได้ จะเพิ่ม logic กรองสิทธิ์ในฝั่ง `Code.gs` ให้
- ฟอร์มสาธารณะไม่มีการยืนยันตัวตนของผู้กรอก (อาจไม่ใช่ตัวนิสิตเองก็ได้) — ถ้าต้องการให้นิสิต login ด้วยอีเมล ku.th ก่อนกรอกฟอร์มด้วย แจ้งได้ จะเพิ่ม Google Sign-In ในหน้า `add-student.html` เช่นเดียวกับแดชบอร์ด
